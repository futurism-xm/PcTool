# 任务栏／托盘切换卡顿修复（2026-09-10）

## 根因与修复

旧流程在仍有 Explorer 子窗口时调用 Shell_NotifyIcon 新增托盘；反方向则在创建任务栏子窗口后删除托盘。托盘布局更新与跨进程子窗口之间形成同步等待。可选计时日志记录到 display.tray.begin 后约 15.5 秒仍未成功，自动重试持续失败，20 秒测试未完成切换。

先结束原生菜单，再发送切换请求；仅结束菜单的中间版本仍复现等待。最终改为：任务栏到托盘先销毁任务栏子窗口，再新增托盘；反方向先移除托盘，再创建任务栏子窗口。入口创建失败保留替代入口并重试。重复 Create 保留有效任务栏窗口，避免无意义重建。

## 验证

- tests/monitor_switch_latency.ps1：真实 Release 进程；从任务栏用实际右键打开菜单，托盘方向经真实托盘回调打开共用菜单；随后均以 SendInput 点击性能监控正文。记录点击到目标入口状态完成时间，同时检查另一入口不存在。
- 修复前20秒等待失败；菜单先关闭的中间版本同样失败，未将此版本算作修复成功。
- 最终版本连续30次切换通过，首次完整测试最慢46.1504毫秒；运行测试后恢复原来的 MonitorInTaskbar 设置。测量包含轮询和测试 API 开销，不代表所有电脑的时延上限。
- 最终构建再次连续30次切换通过，最慢47.9075毫秒，原始数据见 out/monitor-switch-final.json；两种模式及重启恢复测试四次通过。
- 原生任务栏菜单、布局、配置重载、模块边界测试通过；布局新增重复 Create 不重建窗口断言。
- Debug／Release 构建及安装包更新。未实测真实 Explorer 崩溃、系统挂起或混合 DPI 跨屏；本轮没有变更性能采样、快捷键及翻译功能。

复现命令：`pwsh -File tests/monitor_switch_latency.ps1 -Cycles 30 -LimitMs 1000 -ReportPath out/monitor-switch-final.json`。

需要分阶段日志时，在启动测试进程前设置 PCTOOL_MONITOR_TRACE 为本地日志路径；只记录时间及阶段名称，不记录性能数值或用户内容，默认关闭。
