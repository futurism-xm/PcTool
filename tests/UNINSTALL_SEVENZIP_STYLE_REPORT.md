# 采用 7-Zip 的卸载延期清理方式

日期：2026-09-15；版本：0.1.2。

本报告取代此前“占用时重启 Explorer”“延期清理返回 3010 并保留卸载器”的交付行为。用户已选择官方 7-Zip 的处理方式：正常卸载结束，无需立即重启；无法当场删除的文件留待下次正常重启清理。

## 实现

- NSIS 不再调用 `release-shell`，仅刷新关联，不关闭 Explorer 或其他扩展宿主。仍停止本安装任务并验证进程退出。
- 清理脚本的内部 3010 作为“延期登记成功”处理，继续清理卸载器、辅助文件、快捷方式和卸载注册。外部退出码为 0；清除 NSIS 重启标志，避免完成页出现重启选项，但保留 Windows 延期队列。
- 完成详情区区分立即清理和延期清理；确认页说明无需立即重启。实际删除／延期登记失败仍报错。
- 保留同目录重装时撤销旧受管删除记录的修复，以及第三方注册恢复、无关文件保留和路径边界限制。

## 验证

- 隔离 NSIS 测试覆盖无／有独立 7-Zip 注册的首次安装、覆盖安装，DLL 哈希检查及实际 COM 菜单生成。
- 使用安装目录外的隐藏测试进程加载真实 7-Zip DLL，并保持 hive 与额外文件占用。卸载返回 0，所属顽固任务被结束，外部 DLL 宿主仍活着；卸载器、辅助程序和卸载注册移除，被占用 DLL 保留并登记删除。
- 释放测试占用后，仅按队列顺序模拟本测试目录的重启删除；受管目录与文件清理通过，无关文件保留，原 32／64 位注册正确恢复。

- `tests/install_pending_delete_tests.ps1` 串行复跑通过，重装保护和其他软件队列保留正确。首次与隔离安装同时执行时因共享全局队列的断言快照变化失败；待隔离测试结束后重跑通过，检查未残留测试队列项。两类测试应串行执行。
