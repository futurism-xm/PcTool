# 待重启卸载与同目录重新安装

日期：2026-09-15；版本：0.1.2。

## 修复

旧流程只写入文件和注册扩展，没有撤销此前卸载登记的路径删除操作。Windows 重启按路径执行删除时，无法区分旧文件和同路径重新安装的新文件。已确认这是兼容性缺口；用户本次 DLL 丢失缺少重启前队列记录，不能断言一定由此导致。

`manage-data.ps1` 在 Record 阶段、替换任何程序文件之前，检查 PendingFileRenameOperations。只移除当前包受管文件及目录、安装根目录、卸载器和管理标记、受管 Data/Cache 的删除对。保留其他安装、用户文件、重命名操作及旧 DLL 备份清理；影响本次安装的待执行重命名会明确阻止安装。解析本机绝对路径、忽略大小写、检查目录边界和重解析点，遇到异常注册类型或不完整操作对停止安装。写入前重新读取队列，发现变化则重试，并再次检查。

NSIS 安装结束注册前检查两种位数的扩展文件存在，缺失时中止，不报告成功。

## 实测

- `tests/install_pending_delete_tests.ps1` 通过：当前 DLL、主程序、Data/Cache 及根目录的删除记录移除；NT/扩展路径和大小写处理；相邻安装目录、无关文件、重命名对和旧 DLL 清理原序保留；重复安装幂等；覆盖新 DLL 的待重命名操作阻止安装，队列不变。
- 隔离 NSIS 测试通过：有／无先前独立 7-Zip 两种情形，各执行首次安装和覆盖安装，安装前登记旧卸载删除操作，安装后验证队列已清除，两种位数 DLL 的 SHA256 与包内容一致，实际加载 64 位 COM 扩展并生成文件菜单。随后强制卸载、外部占用后重试、第三方注册恢复及无关文件保留均通过。

- v0.1.2 安装包构建通过，包内安装脚本哈希与源码一致，两个扩展 DLL 存在，不包含 docs/tests。SHA256：`E19B5E73ECBC8AA754BFF08AD174333E4F24FFFBCA85FE3CE5CAC4BF6941ABA0`。
