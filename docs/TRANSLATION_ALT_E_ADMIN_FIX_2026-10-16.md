# Alt+E 取词与管理员启动修复（2026-10-16）

## 问题与修复

- **P1，VS 取词失败**：`src/translation/translation_controller.cpp` 中全局快捷键收到 E 后，来源窗口仍会收到 Alt 松键。先松 Alt、再松 E 时，VS 的 WPF 菜单会获得焦点，但 Win32 菜单标志和焦点 HWND 可能不变。原版本在独立 VS 实例中以真实 Alt+E 测得 33 次失败 11 次；双方均为管理员权限，排除了本次故障由权限差引起。
- 仅对已接受的 Alt 取词请求注入带内部标记的菜单抑制按键；显示被动窗口之前保存编辑焦点。来不及抑制时，异步检查来源进程的 UI Automation 菜单，确认退出菜单及恢复编辑焦点后再复制；无法确认则报告失败。普通单独按 Alt 的菜单功能保留。
- 保留来源、请求版本、输入序列、取消和迟到结果保护；UIA 最多一个探测在途。剪贴板支持中间空状态、固定 1.5 秒截止和读取重试，同一已成功读取的序列不重复加锁。有效文字到达即填入并提交翻译。日志不含选中文字或凭据。
- **P1，自启迁移与权限安全**：产品清单改为 `requireAdministrator`。原普通 Run 启动不能可靠启动需要提权的新版程序，因此安装阶段通过 `--configure-startup` 按已有开关迁移，避免等待首次手动运行。
- 新自启任务按用户 SID 和安装路径哈希区分，使用当前用户交互式登录、最高权限，直接执行安装路径程序。任务写入并读回验证成功后才删除属于本安装的旧 Run 值；失败回滚，外来注册保留。关闭自启、升级及卸载按所有权匹配处理，支持隔离测试命名空间。
- 任务及文件夹仅 Administrators/SYSTEM 可修改；检查程序、依赖和祖先目录的 ACL、所有者、固定磁盘及重解析点。安装仅保护受管 payload，延续 Data/Cache 的用户写入规则。自定义目录祖先仍可替换时明确拒绝高权限自启；安装器提示并返回 1603，程序和菜单仍保留，可改装到 Program Files。
