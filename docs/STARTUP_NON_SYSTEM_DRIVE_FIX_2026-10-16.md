# 非系统盘管理员自启修复（2026-10-16）

## 原因

本次告警涉及两件事，均与“必须装 C 盘”无关：

- **P2，磁盘根目录误判**：`src/app/startup_registration.cpp` 把卷根目录的 `DELETE` 权限当作可改名或替换安装路径。此机器 D 盘根目录使用常见数据盘 ACL，普通用户具有 Modify（包含 DELETE），但卷根目录本身不能被改名或删除。这会错误拦截已经保护好的 `D:\PcTool`。
- **真实路径风险**：旧安装位置 `D:\install\PcTool` 的程序文件已保护，但 `D:\install` 自身允许普通用户 Modify，包含改名/删除该目录的权限。只保护程序文件不能阻止上级目录被换掉，因此这里仍需拦截最高权限自启。

## 修复

- 仅在卷根目录检查中排除无效的 `DELETE` 判断。卷根目录的所有者、`WRITE_DAC`、`WRITE_OWNER`、`FILE_DELETE_CHILD` 以及重解析点检查继续保留；普通目录的 DELETE 检查继续保留。
- 权限失败显示具体路径，并明确支持非系统盘的受保护目录；安装器和 README 去除容易被理解为必须安装到 C 盘的建议。
- 当前机器保留 D 盘安装，迁移至 **`D:\PcTool`**。新目录仅 Administrators/SYSTEM 可修改，普通用户可读取执行；用户数据目录沿用既有规则。没有修改共享上级目录 `D:\install` 或 D 盘根目录 ACL。
- 迁移前对原安装 143 个文件完整备份并校验 SHA256；4 个用户数据文件恢复后逐一确认哈希不变。使用正式卸载器撤销旧注册，再通过新安装包部署，更新自启任务、桌面/开始菜单快捷方式及 x86/x64 7-Zip 注册。
